# 需求询问

需求询问采用 grill-me 前置流程：先创建 `plan.md`，再按主题逐步询问 / 拷打，不一次性抛出所有问题。

1. 输出目标：世界书 / 角色卡 / both。
2. 来源类型：原创 / 二创 / 修改已有 JSON / 混合。
3. 项目名与风格。
4. 世界观：规则、势力、冲突、user 可感知边界。
5. 角色：定位、关系、动机、性格、人设禁区。
6. `{{user}}` 边界：不能预设身份、外貌、行动、心理。
7. 开场白：场景、氛围、互动点、可选开场数量。
8. 可选资产：MVU、HTML 状态栏、regex、EJS。
9. 验收标准。

## grill-me 规则

- 每次只问一个问题。
- 每个问题都给出推荐答案。
- 沿决策树逐个解决依赖分支，先确认上游决策，再追问下游细节。
- 如果能通过已有 plan、draft、source、导入结果或代码库探索回答，就自行探索，不重复询问用户。
- 用户每回答一次，必须立即通过 `update_plan` 写入 `plan.md`，记录问题、推荐答案、用户决定、影响范围与状态。
- 不得等全部问题问完后再批量补写 plan；上一轮未记录时，不继续下一轮关键问题。

所有需求和决策都通过 `update_plan` 写入 `plan.md`。
