# 世界观设定方法论

世界观不是百科全书。只写会影响角色行动、剧情冲突、互动规则、场景可用性的设定。删掉后故事仍成立的信息，压缩或暂不写。

世界观总纲先进入 `plan.md`，再拆成世界书条目。条目正文建议使用 XML-wrapped YAML，保存到 `source/entries/*` 后再注册进 `draft/worldbook.yaml`。

## A/B/C 判定

判断标准是：模型对这个世界的底层信息已经知道多少。

| 类型 | 判定 | 写作原则 |
|---|---|---|
| A_real_background | 锚定真实世界地点、时代、行业或学校 | 只写差异信息和虚构层，不复述真实世界常识 |
| B_small_world | 有成熟类型标签：修仙、赛博朋克、末日废土、剑与魔法等 | 在类型套路上定义 1-3 个核心差异 |
| C_large_world | 原创名词、原创规则、原创势力、原创地理占主体 | 分层设计：总纲、速览、详情 |

例：

- A：1995 年东京 + 阴阳师秘密存在。只写 1995 通讯限制、阴阳师组织、隐世规则。
- B：修仙世界 + 灵气来自空间裂缝。重点写裂缝垄断造成的阶层和冲突。
- C：原创浮空城、晶脉能源、七个原创势力。需要总纲、速览、关键详情。

## 维度取舍

不要硬凑维度。每个选中维度都必须回答“它如何影响角色和故事”。

| 维度 | 核心问题 | 写什么 | 不写什么 |
|---|---|---|---|
| `geography` | 世界长什么样，移动如何发生 | 区域功能、关键地点、环境限制、路线与隔离 | 真实地理常识、纯风景散文 |
| `timeline` / `history` | 什么事件塑造当前局势 | 不超过 5 个关键事件、距今时间、后果 | 完整编年史、无关远古史 |
| `factions` | 谁在争夺什么 | 组织定位、诉求、资源、方法、冲突对象 | 只有名字没有立场的空壳阵营 |
| `rules` / `power_system` | 世界如何运转 | 力量来源、使用条件、限制、代价、禁忌 | 类型通用套路，除非有差异 |
| `society` | 人如何被分类和约束 | 阶级、身份、法律、流动渠道、歧视来源 | 没有冲突的扁平社会说明 |
| `technology` | 能做什么、不能做什么 | 关键技术、垄断状态、成本、失败风险 | 标准现代科技清单 |
| `culture` / `custom` | 人如何生活和判断 | 礼仪、称谓、禁忌、节日、婚恋/继承规则 | 与互动无关的风俗堆砌 |

取舍规则：

1. A 类只写虚构层或时代差异。
2. B 类选择 1-3 个核心差异维度。
3. C 类写所有相关维度，但只展开直接影响剧情的部分。
4. 删除测试：删掉该维度后，角色行为或当前冲突会不会变？不会就删。

## 最小设定集

先写 `minimum_setting_set`，再写正文。

```yaml
<minimum_setting_set>
must_have:
  - 没有这条，故事或互动会崩坏的设定
  - 没有这条，角色行动逻辑会错误的设定
can_omit:
  - 可交给模型常识处理的信息
  - 以后剧情需要时再追加的信息
risks:
  - 不写清楚会导致误演的设定
</minimum_setting_set>
```

`must_have` 常见类型：

- `{{user}}` 能否进入、看见、使用、改变某个系统。
- 权力和资源由谁控制。
- 角色为什么不能直接解决问题。
- 某个能力的代价与禁忌。
- 某个地点为什么必须去或不能去。

## 概念功能锚点

原创概念不能只给名字。每个原创名词至少包含：

```yaml
<concept_anchor>
name: 概念名
what: 它是什么
who_uses_it: 谁使用、控制、依赖或受害
why_it_matters: 为什么会影响剧情、关系或互动
conflict: 围绕它产生的冲突
cost_or_limit: 使用、获得、接触它的代价或限制
</concept_anchor>
```

错误：

```yaml
晶脉: 分布于大陆各地的神秘资源
```

可用：

```yaml
晶脉: 大陆地下的结晶矿脉，是驱动魔法装置的唯一能源；帝国矿业公会垄断开采，独立法师无法合法获取；枯竭速度超过再生速度，三个边境城市已因此废弃。
```

## 零度总纲

总纲是后续条目的事实来源，不是小说开篇。使用名词 + 数据 + 逻辑关系，控制在 100-200 字左右。

模板：

```yaml
<world_summary>
name: 中文名 | English Name
type: A_real_background | B_small_world | C_large_world
core_concept: 这个世界最根本的决定性设定
geography: 区域划分 + 关键地点；A 类只写虚构部分
history: 关键事件 + 距今时间 + 当前后果
factions: 组织名称 → 定位 → 诉求 → 冲突对象
rules: 核心机制 + 来源 + 限制 + 代价
society: 身份结构 + 形成原因 + 矛盾点
technology: 关键技术 + 限制条件 + 社会影响
user_boundary: {{user}} 在世界中的可知、可见、可行动边界
</world_summary>
```

零度要求：

- 不使用比喻句。
- 不堆“宏大、古老、复杂、神秘、强盛、繁华”等空词。
- 每行能独立回答一个事实问题。
- A 类不要复述真实世界常识。
- B 类不要重写类型通用设定。

## C 大世界三层结构

C 类世界建议分三层，避免一次展开所有细节。

### 1. 总纲层

100-200 字，说明世界核心逻辑和所有关键维度的一句话摘要。

### 2. 速览层

当维度超过 3 个时使用。每个维度 3-8 条要点，供后续条目快速查阅。

```yaml
<world_overview>
geography:
  - 区域名: 功能、限制、主要冲突
factions:
  - 势力名: 目标、资源、敌对对象
rules:
  - 规则名: 使用条件、代价、禁忌
</world_overview>
```

### 3. 详情层

只展开直接影响角色行为、剧情冲突、玩法互动的维度。没有故事关联的历史、远方国家、完整税制、神话年代先不写。

## 地理 / 区域条目

区域不是风景描写，而是行动空间。

```yaml
<geography>
regions:
  - name: 区域名
    function: 叙事功能；角色为什么会来这里
    environment: 会改变行动的环境特征
    access: 如何进入、谁能进入、有什么限制
    scenes:
      - 地点名: 可发生的互动或冲突
    factions:
      - 在此活动的势力
    risks:
      - 危险、禁忌、监控、资源稀缺等
</geography>
```

拆分建议：

- 信息少时，区域、场景、势力写在同一条 `background` 或 `scene` 里。
- 单个地点有稳定互动、触发词或显隐需求时，拆成 `scene` 条目。
- 单个势力内容足够独立时，拆成 `faction` 条目。
- 区域超过 5 个且互相关联复杂时，先写地理速览。

## 时间线 / 历史条目

历史只写当前仍在产生后果的节点。

```yaml
<timeline>
events:
  - name: 事件名
    time: 距今时间或绝对时间
    cause: 直接原因
    result: 事件结果
    current_impact:
      - 当前角色、势力、地点因此发生了什么变化
    related_entries:
      - 相关角色/势力/地点
</timeline>
```

规则：

- 不写完整编年史。
- 每条历史都通过删除测试：删掉后当前局势或角色行为会不会变？
- 大世界远古史只保留仍在影响现在的后果。
- 从既有剧情材料转化时，剧情条目只写模型不看就会出错的信息，不写给读者看的摘要。

## 势力条目

势力要有目标和方法，不能只有名称和风格。

```yaml
<faction>
name: 势力名
position: 社会定位或控制领域
goal: 当前目标
resources:
  - 掌握的资源、技术、人力或合法性
methods:
  - 常用行动方式
conflicts:
  - target: 冲突对象
    reason: 冲突原因
relationship_to_user: 与 {{user}} 的可见关系或边界
relationship_to_characters:
  - 与核心角色的关系
</faction>
```

## 规则 / 能力体系条目

规则必须有条件、限制和代价。

```yaml
<world_rule>
name: 规则或能力体系名
source: 来源
access: 谁能使用、如何获得
operation: 如何运作
limits:
  - 限制
costs:
  - 代价
forbidden:
  - 禁忌或违法行为
story_impact:
  - 它如何制造冲突、限制角色、推动互动
</world_rule>
```

## 世界书条目拆分建议

| 条目类型 | 内容 | 配置倾向 |
|---|---|---|
| `world_summary` | 总纲、最小设定集、user 边界 | 通常蓝灯，靠前 |
| `background` | 时代差异、社会结构、基础规则 | 蓝灯或按需绿灯 |
| `faction` | 单个势力、组织、国家、宗门 | 有触发词时绿灯 |
| `event` | 关键历史事件、当前剧情节点 | 多数绿灯，按事件 keys |
| `scene` | 地点、区域、可互动场景 | 多数绿灯，`scanDepth=2` |
| `item` | 关键资源、道具、货币、文书 | 绿灯，`scanDepth=2` |
| `ability` | 能力体系、术式、技术 | 绿灯，`scanDepth=2` |

## 常见错误

### A 类复述真实世界常识

错误：

```yaml
东京: 日本首都，位于关东地区，人口众多。
```

可用：

```yaml
东京_虚构层: 阴阳厅总部设于新宿地下 30 米；隐世入口分布在都内 12 座指定神社鸟居；普通人看见入口会自动绕行。
```

### B 类复述类型通用套路

错误：

```yaml
灵气: 天地间游离的能量，修士吸收后提升境界。
```

可用：

```yaml
裂缝灵气: 灵气来自界膜战争留下的空间裂缝；三大宗门各自垄断主裂缝，散修只能吸收稀释残灵，因此修行上限由地理位置和宗门许可决定。
```

### C 类脑补无关历史

错误：列出数千年神话、王朝更替、远古战争，但当前故事只发生在一座学院。

可用：只保留“二十年前学院封印事故导致现任院长禁止学生接触地下层；核心角色的能力失控与该事故有关”。

### 总纲写成散文

错误：

```yaml
衔月城悬浮云海之上，月光流淌在琉璃瓦面，整座城市在银辉中静默呼吸。
```

可用：

```yaml
衔月城: 海拔约 3000m 的浮空都市，人口约 3 万；三座浮空港连接地面；城内移动依赖浮空步道和风力通道；贵族垄断御风术教学资格。
```
