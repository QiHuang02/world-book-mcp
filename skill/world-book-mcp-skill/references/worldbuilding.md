# 世界观设定方法论

世界观不是百科全书。只写会影响角色行动、剧情冲突、互动规则、场景可用性的设定。删掉后故事仍成立的信息，压缩或暂不写。

世界观总纲先进入 `plan.md`，再拆成世界书条目。条目正文建议使用 XML-wrapped YAML，保存到 `source/entries/*` 后再注册进 `draft/worldbook.yaml`。

## 协作纪律

- 用户说什么写什么，不擅自扩展核心设定。
- 如果需要补充，先给 2-3 个具体方向，让用户选择。
- 模型已知的常识不写；用户自定义、差异化、会误演的内容才写。
- 所有原创名词都必须有功能锚点，不允许只堆名字。

## A/B/C 判定

判断标准是：模型对这个世界的底层信息已经知道多少。

| 类型 | 判定 | 写作原则 |
|---|---|---|
| `A_real_background` | 锚定真实世界地点、时代、行业或学校 | 只写差异信息和虚构层，不复述真实世界常识 |
| `B_small_world` | 有成熟类型标签：修仙、赛博朋克、末日废土、剑与魔法等 | 在类型套路上定义 1-3 个核心差异 |
| `C_large_world` | 原创名词、原创规则、原创势力、原创地理占主体 | 分层设计：总纲、速览、详情 |

### A：真实背景

模型知道真实背景，只补充它不知道的东西。

```yaml
<world_summary>
背景: 现代日本，东京都
虚构层:
  学校: 羽丘学院，私立女子高中，有乐队社团
  地点:
    - Live House UNDERGROUND: 地下音乐场地，周末有演出
  特殊规则:
    - 学校禁止学生参加校外商业演出
    - 乐队社团有特批的街头演出许可
user_boundary:
  - 不预设{{user}}是学生、教师或乐队成员，除非用户确认
</world_summary>
```

不要写“东京是日本首都”“日本有便利店”。

### B：小世界

模型知道类型套路，但不知道你的差异设定。只写核心差异。

```yaml
<world_summary>
类型: B_small_world
类型基础: 赛博朋克城市
核心差异:
  - 修行资质由义体神经接口决定
  - 城市执照决定居民能否合法升级义体
  - 黑市诊所可以绕过执照，但会留下可追踪后门
主要冲突:
  - 合法升级权被企业垄断
  - 黑市改造者会被企业安保追捕
</world_summary>
```

不要重写“赛博朋克有霓虹灯、公司、贫富差距”这类通用套路。

### C：大世界

原创设定较多时分三层：

1. 总纲层：100-200 字，说明核心逻辑。
2. 速览层：区域、势力、规则、事件各 3-8 条。
3. 详情层：只展开直接影响角色和剧情的部分。

## 最小设定集

先写 `minimum_setting_set`，再写正文。

```yaml
<minimum_setting_set>
must_have:
  - 没有这条，故事或互动会崩坏的设定
  - 没有这条，角色行动逻辑会错误的设定
can_omit:
  - 可交给模型常识处理的信息
  - 以后剧情需要时再追加的信息
risks:
  - 不写清楚会导致误演的设定
</minimum_setting_set>
```

`must_have` 常见类型：

- `{{user}}` 能否进入、看见、使用、改变某个系统。
- 权力和资源由谁控制。
- 角色为什么不能直接解决问题。
- 某个能力的代价与禁忌。
- 某个地点为什么必须去或不能去。

## 概念功能锚点

原创概念不能只给名字。每个原创名词至少包含：

```yaml
<concept_anchor>
name: 概念名
what: 它是什么
who_uses_it: 谁使用、控制、依赖或受害
why_it_matters: 为什么会影响剧情、关系或互动
conflict: 围绕它产生的冲突
cost_or_limit: 使用、获得、接触它的代价或限制
</concept_anchor>
```

错误：

```yaml
晶脉: 分布于大陆各地的神秘资源
```

可用：

```yaml
晶脉: 大陆地下的结晶矿脉，是驱动魔法装置的唯一能源；帝国矿业公会垄断开采，独立法师无法合法获取；枯竭速度超过再生速度，三个边境城市已废弃。
```

## 零度总纲

总纲是后续条目的事实来源，不是小说开篇。使用名词 + 数据 + 逻辑关系，控制在 100-200 字左右。

```yaml
<world_summary>
name: 中文名 | English Name
type: A_real_background | B_small_world | C_large_world
core_concept: 这个世界最根本的决定性设定
geography: 区域划分 + 关键地点；A 类只写虚构部分
history: 关键事件 + 距今时间 + 当前后果
factions: 组织名称 → 定位 → 诉求 → 冲突对象
rules: 核心机制 + 来源 + 限制 + 代价
society: 身份结构 + 形成原因 + 矛盾点
technology: 关键技术 + 限制条件 + 社会影响
user_boundary: {{user}} 在世界中的可知、可见、可行动边界
</world_summary>
```

零度要求：

- 不使用比喻句。
- 不堆“宏大、古老、复杂、神秘、强盛、繁华”等空词。
- 每行能独立回答一个事实问题。
- A 类不要复述真实世界常识。
- B 类不要重写类型通用设定。

## 维度取舍

每个选中维度都必须回答“它如何影响角色和故事”。

| 维度 | 核心问题 | 写什么 | 不写什么 |
|---|---|---|---|
| `geography` | 世界长什么样，移动如何发生 | 区域功能、关键地点、环境限制、路线与隔离 | 纯风景散文 |
| `timeline` / `history` | 什么事件塑造当前局势 | 不超过 5 个关键事件、距今时间、后果 | 完整编年史 |
| `factions` | 谁在争夺什么 | 组织定位、诉求、资源、方法、冲突对象 | 空壳阵营 |
| `rules` / `power_system` | 世界如何运转 | 力量来源、使用条件、限制、代价、禁忌 | 类型通用套路 |
| `society` | 人如何被分类和约束 | 阶级、身份、法律、流动渠道、歧视来源 | 无冲突社会说明 |
| `technology` | 能做什么、不能做什么 | 关键技术、垄断状态、成本、失败风险 | 标准现代科技清单 |
| `culture` / `custom` | 人如何生活和判断 | 礼仪、称谓、禁忌、节日、婚恋/继承规则 | 无关风俗堆砌 |

## 条目模板

### 地理 / 区域

```yaml
<geography>
regions:
  - name: 区域名
    function: 叙事功能；角色为什么会来这里
    environment: 会改变行动的环境特征
    access: 如何进入、谁能进入、有什么限制
    scenes:
      - 地点名: 可发生的互动或冲突
    factions:
      - 在此活动的势力
    risks:
      - 危险、禁忌、监控、资源稀缺等
</geography>
```

### 时间线 / 历史

```yaml
<timeline>
events:
  - name: 事件名
    time: 距今时间或绝对时间
    cause: 直接原因
    result: 事件结果
    current_impact:
      - 当前角色、势力、地点因此发生了什么变化
    related_entries:
      - 相关角色/势力/地点
</timeline>
```

### 势力

```yaml
<faction>
name: 势力名
position: 社会定位或控制领域
goal: 当前目标
resources:
  - 掌握的资源、技术、人力或合法性
methods:
  - 常用行动方式
conflicts:
  - target: 冲突对象
    reason: 冲突原因
relationship_to_user: 与 {{user}} 的可见关系或边界
relationship_to_characters:
  - 与核心角色的关系
</faction>
```

### 规则 / 能力体系

```yaml
<world_rule>
name: 规则或能力体系名
source: 来源
access: 谁能使用、如何获得
operation: 如何运作
limits:
  - 限制
costs:
  - 代价
forbidden:
  - 禁忌或违法行为
story_impact:
  - 它如何制造冲突、限制角色、推动互动
</world_rule>
```

## 世界书条目拆分建议

| 条目类型 | 内容 | 配置倾向 |
|---|---|---|
| `world_summary` | 总纲、最小设定集、user 边界 | 通常蓝灯，靠前 |
| `background` | 时代差异、社会结构、基础规则 | 蓝灯或按需绿灯 |
| `faction` | 单个势力、组织、国家、宗门 | 有触发词时绿灯 |
| `event` | 关键历史事件、当前剧情节点 | 多数绿灯，按事件 keys |
| `scene` | 地点、区域、可互动场景 | 多数绿灯，`scanDepth=2` |
| `item` | 关键资源、道具、货币、文书 | 绿灯，`scanDepth=2` |
| `ability` | 能力体系、术式、技术 | 绿灯，`scanDepth=2` |

## 检查清单

- [ ] 已判定 A/B/C 类型，并按类型控制展开范围。
- [ ] A 类只写差异和虚构层，没有复述真实世界常识。
- [ ] B 类有 1-3 个核心差异，没有复述类型通用套路。
- [ ] C 类按总纲、速览、详情分层，没有一次展开所有百科细节。
- [ ] 已写 `minimum_setting_set`，区分 `must_have` 和 `can_omit`。
- [ ] 每个原创概念都有 name / what / who_uses_it / why_it_matters / conflict / cost_or_limit。
- [ ] 总纲 100-200 字左右，使用零度写作。
- [ ] 每个维度都通过删除测试：删掉后角色行为或当前冲突会变。
- [ ] 涉及 user 时使用 `{{user}}`，没有预设 `{{user}}` 的性别、外貌、行动或心理。
- [ ] 按 `rules.md` 检查禁词、白描、具体性和第四面墙。
