# 多阶段 EJS 人设

## 概念

多阶段 EJS 人设是指角色的性格调色盘随 MVU 变量（好感度、关系状态、信任度等）变化，通过 EJS 条件渲染在不同阶段展示不同人设内容。

核心结构：

- **底色**：不随阶段变化的性格内核，只写一次
- **主色调/点缀**：每个阶段可以不同
- **通用衍生**：跨阶段始终存在，放在所有条件外
- **阶段专属衍生**：该阶段新出现的行为，不是上一阶段衍生的升级版
- **二次解释**：通用的放条件外，阶段专属的用条件包裹

## 前置条件

- MVU schema 已完成，阶段判定变量已定义（好感度、关系状态等）
- 用户已确认阶段划分和条件边界
- 基础调色盘概念已理解（见 `character-creation.md`）

## 阶段判定条件规划

用一张表格明确每个阶段的触发条件：

```
阶段一（初识期）：好感度 < 150
阶段二（熟悉期）：好感度 >= 150 且 < 400
阶段三（暧昧期）：好感度 >= 400 且关系状态 !== "恋人"
阶段四（恋人期）：关系状态 === "恋人"
```

**条件边界必须无重叠、无遗漏**。数值用 `<` `>=` `&&` 连接。普通 controller 可以用 `else` 兜底；若变量加载顺序经常导致默认分支误触发，可采用保守做法：前置独立未定义检查，并用完整 `else if` 覆盖所有有效区间，正式内容不输出调试警告。

## 两种 EJS 结构方案

### 方案 A：controller + getwi 加载禁用 stage 条目

适用于每个阶段内容超过 200 字的情况。

```
[controller 条目]  ← constant=true, enabled=true, order=100
  ├── 变量读取头
  ├── 条件判断
  └── 用 getwi() 按需加载阶段条目

[stage 条目: 阶段01]  ← enabled=false, order=98
[stage 条目: 阶段02]  ← enabled=false, order=98
[stage 条目: 阶段03]  ← enabled=false, order=98
```

controller 模板：

```javascript
<%_
if (typeof gw === 'undefined') var gw = getvar('stat_data.角色名.好感度', { defaults: 0 });
if (typeof rel === 'undefined') var rel = getvar('stat_data.角色名.关系状态', { defaults: '陌生人' });
_%>

<%_ if (gw < 150) { _%>
<%- await getwi('角色名_阶段01_初识') %>
<%_ } else if (gw < 400) { _%>
<%- await getwi('角色名_阶段02_熟悉') %>
<%_ } else if (rel === '恋人') { _%>
<%- await getwi('角色名_阶段04_恋人') %>
<%_ } else { _%>
<%- await getwi('角色名_阶段03_暧昧') %>
<%_ } _%>

跨阶段通用衍生（始终发送）
```

### 方案 B：单条目内 if/else 分块

适用于每个阶段内容较短（< 200 字）的情况。所有内容写在一个条目中。

```javascript
<%_
if (typeof gw === 'undefined') var gw = getvar('stat_data.角色名.好感度', { defaults: 0 });
_%>

性格调色盘：人的性格就像调色盘，底色是不变的内核
底色：好奇

<%_ if (gw < 150) { _%>
主色调：叛逆、警惕
叛逆衍生一：面对权威时本能地想要反抗
警惕衍生一：从不主动分享个人信息
<%_ } else if (gw < 400) { _%>
主色调：热情、试探
热情衍生一：对待喜欢的事情有着用不完的精力
试探衍生一：会故意说一些暧昧的话观察对方反应
<%_ } else { _%>
主色调：依赖、占有
依赖衍生一：睡觉时会下意识抓住对方的衣角
占有衍生一：看到对方和别人亲近会吃醋
<%_ } _%>

好奇衍生一：对新事物总是忍不住想要尝试（通用，始终发送）
```

### 方案 C：动态世界内容

适用于事件触发、剧情推进指示、行为优先级控制等非角色中心内容。每个条件分支必须是完整自洽的指令性提示词，而不是只有场景描述。

```javascript
<%_ if (getvar('stat_data.角色名.好感度') === undefined) { _%>
{{// 调试：关联变量未定义。正式版本可移除该分支输出。}}
<%_ } else if (getvar('stat_data.角色名.好感度') < 20) { _%>
<plot_guide>
当前角色对 {{user}} 保持警戒。应保持距离感，避免突然亲密。
</plot_guide>
<%_ } else if (getvar('stat_data.角色名.好感度') < 80) { _%>
<plot_guide>
当前关系适合推进共同任务或私下交流，让角色主动提供小范围帮助。
</plot_guide>
<%_ } else if (getvar('stat_data.角色名.好感度') >= 80) { _%>
<event_trigger>
可以安排关键情感或信任事件，但仍不得替 {{user}} 做决定。
</event_trigger>
<%_ } _%>
```

要点：使用小写英文 XML 标签包裹输出片段；避免局部 `let/const`；分支内容要直接指导 LLM 的行为、触发条件和优先级。

## EJS 编写铁律

### 变量声明

```javascript
<%_
if (typeof gw === 'undefined') var gw = getvar('stat_data.角色名.好感度', { defaults: 0 });
if (typeof rel === 'undefined') var rel = getvar('stat_data.角色名.关系状态', { defaults: '陌生人' });
_%>
```

三条铁律：
1. 必须用 `typeof` 防重复声明（多条目可能使用同名变量）
2. 必须用 `var` 声明（不可用 `const` / `let`）
3. 路径必须带 `stat_data.` 前缀

### 条件语法

```javascript
<%_ if (gw < 150) { _%>
阶段一内容
<%_ } else if (gw < 400) { _%>
阶段二内容
<%_ } else { _%>
兜底阶段内容
<%_ } _%>
```

- 使用 `<%_ _%>` 标签（自动去除空白）
- 大括号必须成对闭合
- 最后一个分支用 `else` 兜底，确保无遗漏
- 字符串比较用 `===` / `!==`

### getwi 调用

```javascript
<%- await getwi('条目名') %>
```

- 必须加 `await`
- stage 条目必须 `enabled=false`
- stage 条目不能同时设为 constant

## 条目配置速查

| 条目角色 | constant | enabled | order | position |
|---------|----------|---------|-------|----------|
| controller（含 getwi） | true | true | 100 | after_char |
| stage（被 getwi 加载） | false | false | 98 | after_char |
| 单条目 if/else 型 | true | true | 99 | after_char |

所有条目均设置 `preventRecursion=true`、`excludeRecursion=true`。

## 创作引导流程

### 第一步：确定底色

从用户需求中提取角色最深层的性格基调。底色不随阶段变化，只写一次。

### 第二步：初始阶段主色调/点缀/专属衍生

引导用户写出第一阶段的主色调、点缀和专属衍生。衍生由用户自己创作。

### 第三步：标记通用衍生

询问用户哪些衍生是始终如此的（通用），哪些是只在这个阶段的（专属）。

### 第四步：后续阶段

对每个后续阶段：
1. 主色调/点缀是否有变化
2. 引导写出该阶段的新专属衍生
3. 同一行为在多阶段表现不同 → 归通用衍生，差异在二次解释中说明

### 第五步：通用二次解释

针对通用衍生中容易被 AI 误解的性格点写二次解释。

### 第六步：阶段专属二次解释

对每个阶段的专属衍生写阶段专属二次解释。

## MCP 工具使用

### 创建多阶段 EJS 条目

使用 `create_draft_slice` 创建 `ejs` 类型切片：

```
draft_type: ejs
id: "角色名_性格控制器"
```

在 `data` 中设置：
- `role`: "controller"（方案 A）或 "inline"（方案 B）
- `stages`: 阶段定义数组（可选，用于校验）

### 校验

```
validate_project(scope="ejs")
build_assets(target="ejs")
```

## 自查清单

- [ ] 底色不随阶段变化，只写一次，放在所有条件外
- [ ] 每个阶段的主色调、性格点缀都有对应的衍生
- [ ] 阶段专属衍生是该阶段新出现的行为，不是上一阶段衍生的升级版
- [ ] 通用衍生跨阶段始终存在，放在所有条件外
- [ ] 阶段判定条件的边界值不重叠不遗漏，最后用 else 兜底
- [ ] 每个阶段的二次解释覆盖该阶段所有性格点
- [ ] 通用二次解释放在所有条件外，阶段专属二次解释用条件包裹
- [ ] 变量声明使用 `var` + `typeof` 防重复
- [ ] 变量路径带 `stat_data.` 前缀
- [ ] `getwi()` 前有 `await`
- [ ] stage 条目 `enabled=false`
- [ ] controller 条目 `constant=true`、`enabled=true`
- [ ] 条件中使用 `===` / `!==` 而非 `==` / `!=`

## 常见错误

### 底色放在条件内

```javascript
/* 错误：底色随阶段变化 */
<%_ if (gw < 150) { _%>
底色：好奇
主色调：叛逆
<%_ } else { _%>
底色：温柔    /* 底色不应变化 */
主色调：依赖
<%_ } _%>

/* 正确：底色放在条件外 */
底色：好奇
<%_ if (gw < 150) { _%>
主色调：叛逆
<%_ } else { _%>
主色调：依赖
<%_ } _%>
```

### 通用衍生误放在条件内

```javascript
/* 错误：通用特征只在某阶段出现 */
<%_ if (gw >= 400) { _%>
好奇衍生一：对新事物总是忍不住想要尝试
<%_ } _%>

/* 正确：通用衍生放在所有 if 外面 */
好奇衍生一：对新事物总是忍不住想要尝试
```

### 条件边界遗漏

```javascript
/* 错误：好感度 >= 400 时无内容 */
<%_ if (gw < 200) { _%>
...
<%_ } else if (gw < 400) { _%>
...
<%_ } _%>

/* 正确：用 else 兜底 */
<%_ if (gw < 200) { _%>
...
<%_ } else if (gw < 400) { _%>
...
<%_ } else { _%>
...
<%_ } _%>
```
