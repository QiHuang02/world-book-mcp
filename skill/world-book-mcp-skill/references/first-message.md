# 开场白

开场白写入 `source/fields/first_mes.md`，由 `draft/card.yaml` 的 `first_mes` 引用。备用开场写入 `source/fields/greeting-XX.md`，并加入 `alternate_greetings`。

## 硬性要求

- 使用字面 `{{user}}`。
- 不预设 `{{user}}` 的性别、外貌、行动、心理或无法确认身份。
- 以可互动场景收尾，给用户行动空间。
- 若启用 MVU 或 HTML 状态栏，必须包含 `<StatusPlaceHolderImpl/>`。
- 不写“这是角色卡/开场白/模型输出”。

## 大纲先行

正式写正文前先用大纲锁定开场事实，避免写散文。

```yaml
开场白大纲:
  时间: 具体到足够支撑场景，不写无关日期
  地点: 可互动空间
  在场人物:
    - 角色名: 当前状态
  背景前提:
    - 只写不交代就会误演的事实
  当前状态:
    角色:
      - 可见状态
      - 正在做的事
    外部:
      - 场景中正在发生的事
  {{user}}边界:
    - 不预设性别、外貌、动作、心理
    - 只让场景对{{user}}开放
  互动契机:
    - 角色看见/听见/等待/递出/询问的具体动作
  结束点:
    - 一个未完成动作或一句等待回应的话
```

## 五步锚点

1. 时间/地点锚点。
2. 角色当前状态。
3. 明确出现 `{{user}}`。
4. 互动契机。
5. 开放式结尾。

## 正文写法

- 用具体物件和动作进入场景。
- 角色可以主动说话、递东西、让路、沉默等待。
- 不替 `{{user}}` 回答、不写 `{{user}}` 已经做了什么。
- 不用命运升华句结尾。
- 若有状态栏，把 `<StatusPlaceHolderImpl/>` 放在开场前段或末尾固定位置。

## 备用开场

建议准备 2-4 个备用开场，并在以下维度拉开差异：

- 时间：清晨、深夜、课后、任务前、事故后。
- 空间关系：门口、桌边、走廊、车站、房间外。
- 互动方式：询问、交付物品、求助、对峙、共同等待。
- 氛围：日常、紧张、冷处理、任务导向、重逢。

## 避免

- 对白中过度精确数字。
- 预设 `{{user}}` 行动或心理。
- 封闭式结尾。
- “你终于来了”“你刚刚推门进来”这类预设行动，除非用户已经明确要求。
- “你心里一震”“你看着她”这类心理/动作绑定。

## 自查清单

- [ ] first_mes 引用 `source/fields/first_mes.md`。
- [ ] `{{user}}` 只作为占位符出现，没有替换成“用户”或 `<user>`。
- [ ] 没有预设 `{{user}}` 的身份、外貌、行为、心理。
- [ ] 有明确时间、地点、角色状态和互动契机。
- [ ] 结尾开放，可让用户自由回应。
- [ ] 启用 MVU/状态栏时包含 `<StatusPlaceHolderImpl/>`。
- [ ] 按 `rules.md` 检查反八股和白描。
