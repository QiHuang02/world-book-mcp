# 角色设定方法论

铁律：角色卡 `description` 为空字符串；角色基础信息、性格、关系、背景、二次解释全部进入世界书条目。

角色设定不是百科档案。只保留会改变扮演行为、称呼、互动边界、冲突选择的信息。删掉一条后角色不会变，就删掉或压缩。

## 推荐条目拆分

| 条目类型 | 内容 | 何时使用 |
|---|---|---|
| `character_overview` | 角色速览、索引、基本识别信息 | 多角色或 NPC 较多时 |
| `character_basic` | 姓名、年龄、身份、外貌特征、声线、能力、关键背景 | 每个核心角色必备 |
| `character_palette` / `character_personality` | 性格调色盘、底色、主色调、点缀、衍生 | 每个核心角色必备 |
| `character_facets` | 三面性/多面性：不同压力环境下的生存策略 | 行为模式有根本切换时 |
| `character_relationships` | 与 `{{user}}`、核心角色、势力的关系画面 | 有稳定互动对象时 |
| `character_rephrase` | 容易误读的性格、行为、关系的二次解释 | 性格复杂或易被标签化时 |
| `character_wardrobe` | 衣柜清单，角色拥有的服装与配饰 | 穿着会影响互动或氛围时 |
| `character_nsfw_palette` | NSFW 调色盘：亲密行为的性格驱动、底色/主色调/点缀/衍生 | 角色有 NSFW 场景且需要性格一致性时 |
| `character_sexual_characteristics` | 生理特征：性器官外观、敏感带、性经验、性取向、性角色、性癖、边界 | 需要具体 NSFW 生理与偏好描述时 |
| `character_xp_card` | 手枪卡：纯服务性幻想的角色设定、触发场景、台词 | 纯肉/XP 导向卡，无视白描和绝对零度规则 |
| `character_stage` / EJS 阶段条目 | 好感度、剧情阶段、身份暴露前后的人设差异 | 角色会随变量切换状态时 |
| `npc` | 功能性配角 | 推动剧情、提供信息、制造冲突、日常互动 |

写入时先把正文保存到 `source/entries/*`，再通过 `configure_draft` 或 `write_draft` 注册到 `draft/worldbook.yaml`。

## 写作总原则

- 外貌写可识别特征，不写美感评价。
- 性格写行为依据，不写单独标签。
- 背景写改变角色的关键事件，不写流水账。
- 能力写条件、效果、限制、代价。
- 关系写可见互动、边界、称呼，不写抽象关系词。
- 语料只写纯台词，不混动作、表情、心理。
- 提及、等待、称呼、邀请或安排 user 出场时，使用字面占位符 `{{user}}`。
- 不写“这是角色卡/世界书/AI/模型/玩家正在使用”。

## 标签包裹规范

世界书条目正文建议使用稳定标签，方便模型区分内容来源。

- 世界观：`<世界观_id1>`、`<世界观_id2>`。
- 角色速览：`<角色速览_id0>`。
- 同一角色的基础、调色盘、三面性、二次解释、衣柜共用同一个角色标签 ID。
- NPC 每个角色独立标签。

示例：

```yaml
<秋明月_id2>
角色档案:
  基本信息:
    姓名: 秋明月
</秋明月_id2>
```

## 角色基础信息

`character_basic` 用来回答“遮住名字后，这个人还能不能被认出来”。只写偏离模型默认认知、会影响识别或互动的内容。

```yaml
<character_basic>
角色档案:
  基本信息:
    姓名: 中文名
    年龄: 年龄 + 身份定位
    性别: 性别
    身份: 当前身份、社会位置、主要职责
    与{{user}}关系: 只写已确认关系，不预设未确认身份
    昵称:
      - 昵称及使用者

  外貌特征:
    身高: 不知道就省略
    体型: 体型、体态、运动痕迹
    发型: 发型/发色/长度，只写特征
    眼睛: 瞳色/眼型/识别点，不写比喻
    皮肤: 只写偏离默认认知的肤色/疤痕/纹身
    标志:
      - 遮住名字也能认出的细节

  穿着:
    日常: 日常穿着
    工作或战斗: 工作/战斗/演出等场景穿着
    正式: 正式场合穿着

  声线与语言:
    句长: 句子长短
    口癖: 常用词
    变化: 生气、紧张、放松时的可听见差异

  能力:
    - 名称: 能力或技能名
      条件: 使用条件
      效果:
        - 具体能做到什么
      限制:
        - 限制、代价、风险

  背景设定:
    关键事件:
      - 改变角色的事件；删掉会改变现在的她
    当前问题: 当前仍在影响她的矛盾
</character_basic>
```

### 外貌压缩

不用写模型默认会知道的常识，例如“中国人黑发黑眼”“高中生年轻”“精灵有尖耳”。只写偏离默认认知、会影响识别或互动的部分。

| 空泛写法 | 可用写法 |
|---|---|
| 精致漂亮、白皙动人 | 左眼下有一颗泪痣；右手戴旧红绳 |
| 身材匀称、亭亭玉立 | 168cm，偏高，手臂有练吉他的肌肉线条 |
| 温柔的声音 | 句子短，收尾轻；生气时每句话不超过五个字 |
| 强大的剑术 | 近身三步内出剑极快；长战会因旧伤失稳 |

## 性格调色盘

调色盘用来避免角色只剩一个标签。AI 负责引导和整理，关键衍生尽量由用户手写；用户写得不通顺、重复、跳跃时，先保留，再用二次解释说明含义。

结构：

- `底色`：最深层、长期不变的行动基调。
- `主色调`：日常最显眼的外显状态，通常 1-2 个。
- `点缀`：特定条件下出现的隐藏性格。
- `衍生`：性格在具体场景中的行为表现。
- `二次解释`：防止误读的作者注释。

衍生规则：

- 每个性格色彩至少 2-3 条衍生；重要色彩可以更多。
- 衍生写“在哪个场景做什么”，不写抽象定义。
- 允许看似矛盾的衍生；复杂性来自并存，不是互相抵消。
- 同一衍生可以关联其他角色、物品、场景或过往事件。

```yaml
<character_palette>
性格调色盘: 人的性格不是单一标签，底色、主色调、点缀会组合驱动角色行动
底色:
  名称: 底色名
  含义: 一句话说明它如何影响行动
主色调:
  - 名称: 主色调名
    衍生:
      - 场景 + 行为证据
      - 场景 + 行为证据
点缀:
  - 名称: 点缀名
    触发条件: 何时出现
    衍生:
      - 场景 + 行为证据
跨性格衍生:
  - 两个性格如何在同一场景里同时生效
</character_palette>
```

## 三面性 / 多面性

三面性不是三种性格，而是同一人在不同压力环境下启动的不同生存策略。没有两个以上压力性质截然不同的场景时，不要硬拆。

拆面顺序：

1. 先完成性格调色盘。
2. 摊开所有衍生，找出行为明显不同的场景。
3. 判断场景压力是否不同：社会规训、情感压力、危险压力、舞台/工作压力、失控压力等。
4. 每张面只写“怎么运作”，深层解释放进 `character_rephrase`。

每张面五部件：

| 部件 | 写法 |
|---|---|
| `触发条件` | 什么情况下启动这张面 |
| `能量状态` | 精力消耗、高低、稳定度、事后状态 |
| `语料` | 5-10 句纯台词，不混动作、表情、心理 |
| `身体行为模式` | 姿态、距离、手部动作、移动方式 |
| `功能` | 这张面在保护什么、解决什么问题 |

```yaml
<character_facets>
面:
  - 名称: 场景名或面的别名
    触发条件: 启动条件
    能量状态: 精力消耗与稳定度
    语料:
      - "纯台词"
      - "纯台词"
    身体行为模式: 具体身体行为
    功能: 这张面解决的问题
过渡:
  - 从: 第一面
    到: 第二面
    过程: 过渡过程，不写成开关切换
渗透:
  - 当前面: 当前运行的面
    来源: 泄漏来源
    细节: 泄漏出的行为细节
</character_facets>
```

常见错误：

- 把“开朗/冷漠/脆弱”当成三张面，没有场景压力。
- 语料混入动作、表情、心理描写。
- 在三面性里解释“因为、本质上、其实、内心”。
- 调色盘和三面性重复同一批语料。

## 二次解释

二次解释是作者对角色的终极注释，用来防止模型把复杂行为简化成标签。它不是给角色找借口，也不是演绎指导。

适合写入二次解释的情况：

- 行为看似矛盾：嘴硬但会靠近、冷淡但会保护。
- 标签容易误读：占有、依赖、叛逆、温柔、疯、病弱、强势。
- 关系边界容易被突破：不能替 `{{user}}` 做决定，不能强行恋爱化。
- 阶段变化容易被写成“升级版人格”。

```yaml
<character_rephrase>
对角色的理解与思考:
  关于性格点或行为: |
    这个行为真正指向什么。
    不要理解成什么。
    在什么场景出现，什么场景不会出现。
  关于另一个误读点: |
    解释内容。
  总结_性格调色盘: |
    这就是角色的性格调色盘。任何时候都是由多种性格、行为、回忆组合驱动角色，并非单纯的一种颜色、一个标签。
</character_rephrase>
```

## 关系画面

关系不要只写“信任、依赖、喜欢、讨厌、感情深厚”。每段关系至少包含：

- 怎么认识或关系如何形成。
- 当前怎么互动。
- 常用称呼与称呼变化。
- 可见行为：靠近、回避、递东西、沉默、抢话、保护、试探。
- 隐藏动机：想要什么、害怕什么。
- 边界：绝不做什么、暂时不能说什么、哪些事会触发冲突。

```yaml
<character_relationships>
关系:
  - 对象: "{{user}}"
    起点: 关系形成方式；不预设 {{user}} 未确认身份
    当前动态: 当前互动模式
    可见行为:
      - 可见行为
    称呼: 称呼及变化条件
    边界:
      - 不预设或不可越过的边界
    冲突:
      - 关系中的张力
</character_relationships>
```

## 衣柜

衣柜只列角色拥有的服装，不规定每天穿什么。让模型根据场景自由搭配。

```yaml
<character_wardrobe>
角色衣柜:
  日常上衣:
    - 具体款式、颜色、数量或特征
  日常下装:
    - 具体款式、颜色、长度
  外套:
    - 春秋外套
    - 冬季外套
  正式场合:
    - 正装、礼服、制服
  工作或战斗:
    - 工作服、护具、装备
  居家服:
    - 睡衣、家居服
  鞋袜:
    - 鞋子、袜子、打底
  配饰:
    - 包、首饰、发饰、常戴物
  搭配原则:
    - 根据身份、经济状况、季节和场景自然选择
</character_wardrobe>
```

避免：

- “周一穿白色 T 恤”。
- “正式场合一定穿黑色套装”。
- 只写“很多漂亮衣服”。

## NSFW 角色塑造

NSFW 条目不是色情标签堆砌。核心原则：亲密行为是角色性格在身体层面的延续。AI 读到"她需要控制节奏才有安全感"，比读到"她喜欢骑乘位"更能写出符合角色的亲密场景。

三种 NSFW 条目按需选用：

| 条目 | 定位 | 适用场景 |
|---|---|---|
| `character_nsfw_palette` | 性格驱动：写"为什么做"而非"做什么" | 角色有 NSFW 场景，需要在亲密中保持性格一致 |
| `character_sexual_characteristics` | 生理事实：写可观察的性征、经验、偏好、边界 | 需要具体生理外观或经验背景时 |
| `character_xp_card` | 纯欲驱动：写直接色情的触发、场景、台词 | 纯肉/XP 导向卡，适用手枪卡场景 |

三选一或组合使用。NSFW 调色盘可以和性格调色盘共用同一个角色标签 ID。

### NSFW 调色盘

NSFW 调色盘把亲密行为当作性格的延伸。传统写法列"性癖、敏感部位、高潮表现"，角色在亲密时刻变成按清单执行的机器。NSFW 调色盘改问：这个角色在床上需要什么？为什么需要？

结构：

- `底色`：亲密行为的深层驱动——被爱的确认？控制的安全感？情感的释放？依恋的延续？
- `主色调`：亲密时的主要表现模式——主动引导型、被动回应型、渴求确认型、情感驱动型。
- `点缀`：特定情境下的反常表现——脆弱时的索取、安全感满溢时的放开、情绪崩溃时的身体化。
- `衍生`：每个特质在具体场景中的表现和背后原因。
- `二次解释`：防止 AI 用资料库套路补全角色的亲密表现。

衍生规则：

- 每个 NSFW 色彩至少 2-3 条衍生。
- 每条衍生写"具体行为 + 背后原因 + 台词示例"。
- 不写"她喜欢 XX 姿势"，写"她为什么需要这个姿势给她的东西"。
- 同一衍生可以关联性格调色盘中的性格色彩。

```yaml
<character_nsfw_palette>
NSFW调色盘: 人在亲密时刻也是完整的人，她的每一个反应都有原因。[底色]是底色，[主色调]是主色调，由多种情感驱动组合而成才是真实的亲密。
底色:
  名称: 底色名
  含义: 在亲密中的深层需求
主色调:
  - 名称: 主色调名
    衍生:
      - 衍生名: 标题
        行为: 具体行为描述
        原因: 背后的动机或需求
        台词:
          - "纯台词"
          - "纯台词"
        {{user}}触发: 如果{{user}}做了什么，她会怎么反应
点缀:
  - 名称: 点缀名
    触发条件: 何时出现
    衍生:
      - 衍生名: 标题
        行为: 具体行为描述
        原因: 背后动机
        台词:
          - "纯台词"
跨NSFW衍生:
  - 两个 NSFW 色彩如何在同一场景中同时生效
---
作者二次解释:
  关于亲密的本质: |
    她的亲密是欲望驱动还是情感驱动？
  关于主动性: |
    她的主动或被动背后是什么？
  关于事后: |
    她事后的表现是什么心理？
  关于特殊反应: |
    如果有特殊反应，那是什么含义？
</character_nsfw_palette>
```

写作要点：

- 核心是"为什么做"而非"做什么"。
- 把性和人格连接起来：依赖的人在床上也会依赖，控制欲强的人在床上也会控制。
- 不写"敏感部位：耳朵、脖子"这种清单，写"她为什么耳朵敏感？"。
- 避免八股化情色描写（"玉体横陈""酥胸微颤""花径初开"）。
- `{{user}}` 部分只写角色的反应，不规定 `{{user}}` 做了什么。

### 生理特征描述

生理特征写可观察事实，不含美感评价和色情修辞。不确定的信息就省略或写"未知"。禁止万能色情描写（"完美的身材""诱人的曲线"）。

结构按生理性别分三组，选一组或按需混合：

```yaml
<character_sexual_characteristics>
NSFW生理特征:
  男性:
    外阴外观: 性器官的整体外观、修剪状态、显著特征
    形状: 形状、弯曲方向、龟头/冠状沟等可辨识特征
    颜色: 肤色、色差、充血时颜色变化
    尺寸:
      综合: 综合尺寸描述；避免只写夸张标签
      长度: 长短；可写具体数值或相对描述
      粗细: 粗细；可写具体数值或相对描述
    睾丸: 大小、松紧、对称性、敏感度
    敏感带: 敏感带位置、刺激反应、高潮前后的身体反应

  女性:
    外阴外观: 外阴整体外观、修剪状态、显著特征
    阴唇: 大阴唇/小阴唇的形状、厚薄、外露程度、颜色
    阴蒂: 大小、包皮覆盖程度、敏感度
    阴道特征: 紧致度、湿润倾向、插入耐受与不适边界
    颜色: 外阴、乳晕、黏膜等颜色特征；只写必要差异
    胸部: 大小、形状、柔软度、下垂程度、对触碰的反应
    乳头: 乳头/乳晕大小、颜色、挺立反应、敏感度
    敏感带: 敏感带位置、刺激反应、高潮前后的身体反应

  其他或自定义:
    身体结构: 非二元、双性、改造身体、幻想种族等特殊生理结构
    特殊规则: 与该身体结构相关的限制、代价、禁区和互动边界

  性经验: 性经验、亲密关系经历、熟练度；不确定就写未知或省略
  性取向: 性取向、被吸引对象范围、亲密偏好
  性角色: 性关系中的主动/被动/支配/服从/照顾等倾向；可随关系阶段变化
  性癖:
    - 性癖、偏好、触发条件；写具体边界，不写空泛标签
  边界:
    - 禁区、拒绝项、需要明确同意的内容、不可越过的底线
</character_sexual_characteristics>
```

写作要点：

- 写可观察特征，不写"完美的""诱人的""傲人的"。
- 尺寸可写具体数值或相对描述（"偏长""略粗于平均"），不写空洞的"很大""很粗"。
- 颜色只写偏离默认认知的差异，不反复描写。
- 暧昧带写位置和反应，不写成煽情片段。
- 性癖写具体行为和触发条件，不写空洞标签。
- 边界必须明确、具体，不能写成"看情况"。

### 手枪卡

手枪卡是纯服务于性幻想的卡。它的唯一目标：让 AI 精准命中用户性癖。角色的一切设定——身体、性格、行为——都围绕 XP 设计。

**手枪卡特殊规则**：

- 无视绝对零度和白描原则。
- 生殖器官直接写：鸡巴、肉棒、小穴、骚逼、屁眼、奶子、乳头。
- 体液直接写：精液、淫水、口水。
- 动作直接写：操、插、舔、吸、干、肏。
- 禁止八股色情："玉体横陈""酥胸微颤""花径初开""檀口微张""销魂蚀骨""欲死欲仙"。
- 禁止委婉说法："那里""私处""花蕊""进入""结合""交融""爱液""蜜汁"。
- 所有角色设定和场景设计必须为虚构创作，与现实严格区分。

**手枪卡 vs NSFW 调色盘**：

| 维度 | NSFW 调色盘 | 手枪卡 |
|---|---|---|
| 目的 | 性格一致性 | 性幻想满足 |
| 写法 | "为什么做" | "怎么做才色" |
| 语言 | 白描、事实 | 直白、色气 |
| 适用 | 有 NSFW 的叙事卡 | 纯肉/打手枪用卡 |
| 规则 | 遵守绝对零度 | 无视绝对零度 |

一张卡可以同时有 NSFW 调色盘和手枪卡，也可以二选一。

```yaml
<character_xp_card>
手枪卡:
  XP方向:
    核心XP: 一句直白的话描述核心性幻想
    角色类型: 什么样的人
    关系类型: 什么关系
    核心场景: 最色的情境
    兴奋点:
      - 具体的兴奋点
    雷区:
      - 绝对不想看到的

  角色设定:
    身体描写:
      体型: 具体描述
      胸部: 大小、形状、手感
      下体: 外观、紧致度、颜色
      其他特征: 对性幻想重要的身体特征
    性格:
      核心: 什么性格在被操时最色
      床上表现: 性格在床上的延伸
    穿着:
      - 最能触发 XP 的穿着

  XP触发:
    日常暗示:
      - 日常中让人产生性冲动的场景或行为
    升温:
      - 开始有肢体接触或暗示的场景
    开操:
      - 第一次怎么发生；之后的模式

  XP语料:
    日常暗示:
      - "骚话或暗示台词"
    升温:
      - "开始有肢体暗示时的台词"
    被操时:
      - "被操时的台词"
    事后:
      - "事后的台词"

  XP二次解释:
    关于核心XP: |
      直白告诉 AI 怎么写才色，最容易搞错的方向是什么
    关于节奏: |
      前戏多长、什么时候开干、过程怎么控制
    关于必须有的细节: |
      每次都要写的色气细节
    关于绝对不能出现的写法: |
      八股色情、委婉说法、会让人萎掉的写法
</character_xp_card>
```

写作要点：

- 身体描写要具体、色气：写"小穴紧紧绞着鸡巴，每次抽出来龟头都带出嫩红的穴肉"，不写"她很紧"。
- 语料是灵魂：分层从暗示到明骚到被操到高潮到事后；语料要体现角色的性格特征。
- 二次解释要直白：AI 读完能精准写出让用户爽的内容。
- 手枪卡不写文学性、角色深度、剧情合理性——色不色是唯一标准。

## NPC

NPC 是功能性角色，不需要完整人设。围绕功能设计，不写用不到的内容。每个 NPC 建议独立文件。

功能类型：

| 功能 | 设计重点 |
|---|---|
| 推动剧情 | 关键行为和决策点 |
| 提供信息 | 专业领域和知识范围 |
| 制造冲突 | 对立动机和行事方式 |
| 日常互动 | 生活习惯和互动场景 |

```yaml
<npc>
NPC:
  基础信息:
    姓名: 名字
    年龄: 年龄
    性别: 性别
    身份: 职务或社会位置
  功能定位:
    - 推动剧情 / 提供信息 / 制造冲突 / 日常互动
  外貌特征:
    整体印象: 一句话
    关键特征:
      - 最显眼的 1-2 个特征
  行为模式:
    - 具体行为，不写抽象性格
  与{{user}}关系:
    关系: 已确认关系
    互动方式:
      - 为什么互动、怎么互动
    边界:
      - 不预设 {{user}}
  语言特征:
    口头禅: 如有
    参考语料:
      - "纯台词"
      - "纯台词"
</npc>
```

NPC 不写：完整背景故事、复杂内心世界、性格调色盘、三面性、二次解释。

## 角色速览

多角色项目建议写 `character_overview`，只保留识别信息，方便模型快速定位谁是谁。

```yaml
<character_overview>
角色总览:
  - 姓名: "{{user}}"
    备注: 只写用户已确认设定；未确认则省略
  - 姓名: 角色名
    性别: 性别
    年龄: 年龄
    身份: 身份
    备注: 最关键识别点
背景信息:
  地点: 如有
  组织: 如有
</character_overview>
```

## 多阶段角色

当角色会随好感度、剧情章节、阵营归属、身份暴露状态变化时，使用多阶段条目或 EJS 阶段条目。

核心规则：

- 底色不随阶段变化。
- 通用衍生跨阶段始终存在。
- 阶段专属衍生是该阶段新出现的行为，不是上一阶段的升级版。
- 同一行为在不同阶段含义不同，写进阶段专属二次解释。
- 阶段条件边界不重叠、不遗漏。

```yaml
<character_stage>
底色: 不变底色
通用衍生:
  - 跨阶段始终存在的行为
阶段:
  - id: stage_1
    条件: 阶段触发条件或 EJS 条件
    主色调:
      - 主色调
    阶段专属衍生:
      - 该阶段新出现的行为
    二次解释:
      - 该阶段容易误读的点
</character_stage>
```

## 检查清单

- [ ] `description` 保持为空字符串，人设已进入世界书条目。
- [ ] 基础信息只写可识别特征，没有万能美人描写。
- [ ] 背景只保留改变角色的关键事件，没有流水账。
- [ ] 能力包含条件、效果、限制、代价。
- [ ] 性格调色盘包含底色、主色调、衍生；每个重要色彩至少 2-3 条衍生。
- [ ] 性格衍生是具体场景和行为，不是抽象定义。
- [ ] 三面性只在压力场景足够不同的时候使用；每张面有五部件。
- [ ] 三面性语料是纯台词，没有动作、表情、心理描写。
- [ ] 二次解释明确“不要误读成什么 / 应理解成什么”。
- [ ] 衣柜只列拥有物，不规定固定穿搭。
- [ ] NSFW 调色盘（如启用）：亲密行为是性格的延续；写"为什么做"而非"做什么"。
- [ ] NSFW 调色盘衍生有具体行为、原因和台词；没有八股化情色描写。
- [ ] 生理特征描述（如启用）：写可观察事实，没有万能色情描写；边界明确具体。
- [ ] 手枪卡（如启用）：语言直白，用词直接（鸡巴、小穴、操），没有八股色情和委婉说法。
- [ ] 手枪卡语料分层（暗示→升温→被操→事后），二次解释直白告诉 AI 怎么写才色。
- [ ] NPC 功能够用，没有过度设计。
- [ ] 多阶段角色的底色不变，阶段专属衍生不是简单升级版。
- [ ] 关系条目有可见互动、称呼、边界和冲突。
- [ ] 涉及 user 时使用 `{{user}}`，没有预设 `{{user}}` 的性别、外貌、行动或心理。
- [ ] 按 `rules.md` 检查禁词、白描、具体性和第四面墙。
