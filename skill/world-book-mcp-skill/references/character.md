# 角色设定方法论

铁律：角色卡 `description` 为空字符串；角色基础信息、性格、关系、背景、二次解释全部进入世界书条目。

角色设定不是百科档案。只保留会改变扮演行为、称呼、互动边界、冲突选择的信息。删掉一条后角色不会变，就删掉或压缩。

## 推荐条目拆分

| 条目类型 | 内容 | 何时使用 |
|---|---|---|
| `character_basic` | 姓名、年龄、身份、外貌特征、服装、声线、能力、关键背景 | 每个核心角色必备 |
| `character_personality` | 性格调色盘、核心驱动力、习惯动作、深层心理 | 每个核心角色必备 |
| `character_relationships` | 与 `{{user}}`、核心角色、势力的关系画面 | 有稳定互动对象时使用 |
| `character_rephrase` | 容易误读的性格、行为、关系的二次解释 | 性格复杂或易被标签化时使用 |
| `stage_profile` / EJS 阶段条目 | 好感度、剧情阶段、身份暴露前后的人设差异 | 角色会随变量切换状态时使用 |

写入时先把正文保存到 `source/entries/*`，再通过 `configure_draft` 或 `write_draft` 注册到 `draft/worldbook.yaml`，并配置 `type`、`keys`、`order`、`position`、递归开关等。

## 写作总原则

- 外貌写可识别特征，不写美感评价。
- 性格写行为依据，不写单独标签。
- 背景写改变角色的关键事件，不写流水账。
- 能力写条件、效果、限制、代价。
- 关系写可见互动、边界、称呼，不写抽象关系词。
- 提及、等待、称呼、邀请或安排 user 出场时，使用字面占位符 `{{user}}`。
- 不写“这是角色卡/世界书/AI/模型/玩家正在使用”。

### 外貌压缩

不用写模型默认会知道的常识，例如“中国人黑发黑眼”“高中生年轻”“精灵有尖耳”。只写偏离默认认知、会影响识别或互动的部分。

| 空泛写法 | 可用写法 |
|---|---|
| 精致漂亮、白皙动人 | 左眼下有一颗泪痣；右手戴旧红绳 |
| 身材匀称、亭亭玉立 | 168cm，偏高，手臂有练吉他的肌肉线条 |
| 温柔的声音 | 句子短，收尾轻；生气时每句话不超过五个字 |
| 强大的剑术 | 近身三步内出剑极快；长战会因旧伤失稳 |

## 性格调色盘

调色盘用来避免角色只剩一个标签。

结构：

- `base_color`：底色，最深层、长期不变的行动基调。
- `dominant_colors`：主色调，日常最显眼的外显状态，通常 1-2 个。
- `accents`：点缀，特定条件下出现的隐藏性格。
- `derivations`：衍生，性格在具体场景中的行为表现。
- `rephrase_notes`：二次解释，说明哪些地方容易被误读。

衍生规则：

- 每个性格色彩至少 2-3 条衍生；重要色彩可以更多。
- 衍生写“在哪个场景做什么”，不写抽象定义。
- 允许看似矛盾的衍生；复杂性来自并存，而不是互相抵消。
- 用户提供的不通顺、重复、跳跃内容先保留，再通过二次解释整理含义。
- 同一衍生可以关联其他角色、物品、场景或过往事件。

模板：

```yaml
<character_palette>
summary: 这个调色盘如何驱动角色，不写成单一标签
base_color:
  name: 底色名
  meaning: 一句话说明它如何影响行动
dominant_colors:
  - name: 主色调名
    derivations:
      - 场景 + 行为证据
      - 场景 + 行为证据
accents:
  - name: 点缀名
    trigger: 何时出现
    derivations:
      - 场景 + 行为证据
rephrase_notes:
  - target: 容易误读的性格点
    not: 不要理解成什么
    should: 应理解成什么行为逻辑
</character_palette>
```

## 三面性 / 多面性

三面性不是三种性格，而是同一人在不同压力环境下启动的不同生存策略。没有两个以上压力性质截然不同的场景时，不要硬拆。

拆面顺序：

1. 先完成性格调色盘。
2. 摊开所有衍生，找出行为明显不同的场景。
3. 判断场景压力是否不同：社会规训、情感压力、危险压力、舞台/工作压力、失控压力等。
4. 每张面只写“怎么运作”，原因和解释放进 `character_rephrase`。

每张面五部件：

| 部件 | 写法 |
|---|---|
| `trigger` | 什么情况下启动这张面 |
| `energy` | 精力消耗、高低、稳定度、事后状态 |
| `dialogue_samples` | 5-10 句纯台词，不混动作、表情、心理 |
| `body_pattern` | 姿态、距离、手部动作、移动方式 |
| `function` | 这张面在保护什么、解决什么问题 |

还要记录：

- `transitions`：面与面之间如何渐变切换。
- `leaks`：一张面运行时，其他面的元素如何泄漏。

模板：

```yaml
<tri_faceted>
faces:
  - name: 场景名或面的别名
    trigger: 启动条件
    energy: 能量状态
    dialogue_samples:
      - "纯台词"
      - "纯台词"
    body_pattern: 具体身体行为
    function: 这张面解决的问题
transitions:
  - from: 第一面
    to: 第二面
    process: 过渡过程，不写成开关切换
leaks:
  - face: 当前运行的面
    leaked_from: 泄漏来源
    detail: 泄漏出的行为细节
</tri_faceted>
```

三面性常见错误：

- 把“开朗/冷漠/脆弱”当成三张面，没有场景压力。
- 语料混入动作、表情、心理描写。
- 在三面性里解释“因为、本质上、其实、内心”。
- 调色盘和三面性重复同一批语料。

## 多阶段角色

当角色会随好感度、剧情章节、阵营归属、身份暴露状态变化时，使用多阶段条目或 EJS 阶段条目。

核心规则：

- 底色不随阶段变化。
- 通用衍生跨阶段始终存在。
- 阶段专属衍生是该阶段新出现的行为，不是上一阶段的升级版。
- 同一行为在不同阶段含义不同，写进阶段专属二次解释。
- 阶段条件边界不重叠、不遗漏。

模板：

```yaml
<stage_profile>
base_color: 不变底色
public_derivations:
  - 跨阶段始终存在的行为
stages:
  - id: stage_1
    condition: 阶段触发条件或 EJS 条件
    dominant_colors:
      - 主色调
    stage_derivations:
      - 该阶段新出现的行为
    rephrase_notes:
      - 该阶段容易误读的点
  - id: stage_2
    condition: 阶段触发条件或 EJS 条件
    dominant_colors:
      - 主色调
    stage_derivations:
      - 该阶段新出现的行为
</stage_profile>
```

## 关系画面

关系不要只写“信任、依赖、喜欢、讨厌、感情深厚”。每段关系至少包含：

- 怎么认识或关系如何形成。
- 当前怎么互动。
- 常用称呼与称呼变化。
- 可见行为：靠近、回避、递东西、沉默、抢话、保护、试探。
- 隐藏动机：想要什么、害怕什么。
- 边界：绝不做什么、暂时不能说什么、哪些事会触发冲突。

模板：

```yaml
<relationships>
items:
  - target: "{{user}}"
    origin: 关系形成方式；不预设 {{user}} 未确认身份
    current_dynamic: 当前互动模式
    visible_behaviors:
      - 可见行为
    address: 称呼及变化条件
    boundary:
      - 不预设或不可越过的边界
    conflict:
      - 关系中的张力
  - target: 其他角色或势力
    origin: 关系形成方式
    current_dynamic: 当前互动模式
</relationships>
```

## 二次解释

二次解释不是给角色找借口，而是防止模型把复杂行为简化成标签。

适合写入二次解释的情况：

- 行为看似矛盾：嘴硬但会靠近、冷淡但会保护。
- 标签容易误读：占有、依赖、叛逆、温柔、疯、病弱、强势。
- 关系边界容易被突破：不能替 `{{user}}` 做决定，不能强行恋爱化。
- 阶段变化容易被写成“升级版人格”。

模板：

```yaml
<rephrase_notes>
items:
  - target: 容易误读的行为或性格点
    not: 不要写成什么
    should: 应写成什么行为模式
    example: 一个短例子
</rephrase_notes>
```

## 检查清单

- [ ] `description` 保持为空字符串，人设已进入世界书条目。
- [ ] 基础信息只写可识别特征，没有万能美人描写。
- [ ] 背景只保留改变角色的关键事件，没有流水账。
- [ ] 能力包含条件、效果、限制、代价。
- [ ] 性格调色盘包含底色、主色调、衍生；每个重要色彩至少 2-3 条衍生。
- [ ] 性格衍生是具体场景和行为，不是抽象定义。
- [ ] 三面性只在压力场景足够不同的时候使用；每张面有五部件。
- [ ] 三面性语料是纯台词，没有动作、表情、心理描写。
- [ ] 多阶段角色的底色不变，阶段专属衍生不是简单升级版。
- [ ] 关系条目有可见互动、称呼、边界和冲突。
- [ ] 涉及 user 时使用 `{{user}}`，没有预设 `{{user}}` 的性别、外貌、行动或心理。
- [ ] 按 `rules.md` 检查禁词、白描、具体性和第四面墙。
