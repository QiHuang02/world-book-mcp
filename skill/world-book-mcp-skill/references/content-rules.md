# 内容规则

> 边界：MCP server 只做 JSON/schema/协议/结构/安全校验；本文件负责所有内容审美、禁词、八股文、具体性和写作质量判断。交付前由宿主 AI 按本文件自查，不再调用 MCP 内容 lint 工具。

## 数据库式 YAML

世界书 `entry` 内容优先使用 XML 包裹 YAML，短字段、短句、具体事实。避免整段散文塞进条目。裸 YAML 文档分隔符 `---` 不应进入成品内容；用 XML 标签包裹 YAML。

## 简体中文与命名

所有条目内容、变量名、角色名、地名默认使用简体中文。不使用繁体字或日文汉字（如“桜/宮/靜/繪”应转为“樱/宫/静/绘”）。二创材料转化时先统一为简体再写入 draft。

## 外貌

只写可辨识特征：发色、发型、衣物磨损、姿态、标志物、习惯动作。避免“精致、白皙、漂亮、帅气、完美”等万能审美词。遮住名字仍认不出角色，说明外貌信息不足。

## 背景与关系

背景只写关键事件和后果。关系写具体画面、债务、承诺、误会、边界，不写“感情深厚”“关系很好”。

## 性格

性格必须有行为依据。不写“温柔/善良/冷酷/强大”这类裸标签；写角色在具体压力、关系、目标下怎样行动。

## 物品与能力

- 服装：写外观、材质、穿戴场景，不写优缺点评测。
- 特殊道具：写外形、玩法、限制、代价，不写无意义精确尺寸。
- 能力：写“触碰 X 可以做到 Y，限制 Z”，不写“威力强大”。

## 禁词与八股化审查

以下规则是 skill 层主观偏好和写作策略，不属于 MCP server 校验。命中后由宿主 AI 直接改写或记录用户决策。

### 量子词 / 模糊程度词

禁用：一丝、一缕、一抹、些许、微微、隐约、不易察觉、不易觉察、难以察觉。

改法：删掉程度副词，改为可观察事实。

### 感知词 / 作者视角判断

禁用或慎用：看起来、听起来、显得、似乎、仿佛、好像、看起来像、仿佛在、像是在。

改法：只写角色能看到/听到/触到的动作、物件、环境变化。

### 对比词 / 总结式判断

禁用：鲜明对比、形成对比、截然不同、反差。

改法：直接并列两组事实，不替读者总结“形成对比”。

### 破折号偏好

禁用解释性破折号：——、—、–。尤其避免“动作——解释”“名词——定义”的八股句。

改法：拆成短句，或用冒号/列表表达结构信息。

### 八股微表情

禁用或高度警惕：弧度、弯起嘴角、翘起嘴角、嘴角上扬、嘴角微微上扬、勾唇、眸光、眼底、喉结、指节发白、指尖微微泛白、咬住嘴唇、眼中闪过一丝。

改法：写真实动作链、身体位置、手里物件、环境互动；不要用同一套微表情替代人物反应。

### 语气声线标签

禁用词：温柔的语气、冰冷的声音、沙哑地说、低沉地说、柔声说。

禁用模式：带着 XX 的口吻、用 XX 的语气、充满 XX 的味道。

改法：保留对白内容，让词序、停顿、动作或上下文体现语气。

### 极端情绪词

禁用或慎用：极度、万分、无比、崩溃、撕心裂肺、万念俱灰、陷入极大的。

改法：写行为后果，例如“连续三天没回消息”“把杯子放回原位又拿起”。

### 比喻禁区

高风险廉价意象：石子、湖面、涟漪、拉满的弓、琴弦、闪电、晨光、星辰、落叶、像一道。

确需比喻时必须具体、稀少、可替代性低；否则转为白描。

### 模糊修饰词

禁用或慎用：几乎、如同、宛如、深深的、某种、难以言说、说不清。

改法：给出明确数量、动作、位置、对象，或直接删除。

### 否定转折八股句式

慎用：“不是……是……”“没有……而是……”。

改法：直接写肯定句，不先否定再解释。

### 对白中的精确数字

对白里出现两位数以上精确数字时复核是否必要。角色自然说话通常用概数；设定字段可保留精确数字。

## 具体性

禁止“某城市、某组织、某学校、某地点、某人物、某家族、待定、TODO、TBD、占位”。未知内容应成为 pending decision，不得自行捏造或用模糊词替代。

禁止抽象标签：温柔善良、感情深厚、关系很好、性格复杂、很有魅力、十分神秘。改为具体事件、行为边界或互动证据。

## 第四面墙

成品条目不得出现“角色卡、世界书、AI、模型、prompt、玩家正在使用”等工具层表述。plan 与内部日志可以记录工具信息，draft content 不可以。

## {{user}} 占位符规则

- 开场白和世界书条目中涉及 user 时，优先使用 `{{user}}` 或 `<user>` 占位符。
- 禁止替 user 说话、行动、决定外貌、性别、身份、房间或后续选择。
- 二创中若用户明确让 user 扮演原著已有角色，可使用该角色名；否则使用占位符。

## 自查流程

1. 先运行 MCP 结构校验：`validate_draft(scope="worldbook" | "character_card" | "delivery")`。
2. 再由宿主 AI 按本文件人工审查内容，不依赖 MCP 返回禁词结果。
3. 命中禁词/八股/抽象标签时直接改写 draft，或记录用户决策。

自查问题：

- 是否 XML 包裹 YAML？
- 是否全简体？
- 是否无占位词/TODO？
- 是否无禁词与解释性破折号？
- 是否无作者视角解释？
- 是否没有替 user 做决定？
- 外貌是否有辨识度？性格/关系是否有证据？
