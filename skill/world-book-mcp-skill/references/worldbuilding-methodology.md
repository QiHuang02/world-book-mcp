# 世界观设计方法论

本文指导如何从零设计世界观并转化为世界书条目。设计阶段只输出结构化概念，不写条目内容；条目化由 `create_draft_slice(draft_type="entry")` + `update_entry_content` / `update_entry_config` 完成。

## 一、世界观类型判定

收到用户需求后，首先判定世界观规模。判定依据：**AI 对这个世界的底层有多少已知信息？**

| 类型 | 判定标准 | 设计原则 |
|------|---------|---------|
| A 类：真实背景 | 世界锚定在现实（现代东京、民国上海等），AI 数据库已掌握绝大部分信息 | 只设计虚构层，真实部分不写 |
| B 类：小世界 | 用户给出成熟类型标签（修仙、赛博朋克、克苏鲁等），AI 知道通用套路但不了解具体设定 | 在通用套路之上定义 1-3 个核心差异 |
| C 类：大世界 | 完全原创世界，原创种族/力量/地理/历史，AI 认知为零 | 分层设计：总纲→速览→详情 |

**MCP 对接**：判定结果记入 plan：

```text
update_plan(mode="replace_section", section="5. 世界观设定", content="类型：B类（修仙+独创灵脉体系）\n核心差异：...")
```

## 二、维度取舍

| 维度 | 核心问题 | 写什么 | 不写什么 |
|------|---------|--------|---------|
| 地理 | 世界长什么样？ | 独特区域、关键地点及叙事功能 | AI 已知的真实地理 |
| 历史 | 什么事件塑造了现在？ | 改变格局的关键事件（≤5 个） | 完整编年史 |
| 势力 | 谁在争夺什么？ | 名称、定位、诉求、冲突点 | 没有故事关联的空壳势力 |
| 规则 | 世界怎么运转？ | 力量体系的来源/运作/限制/代价 | 通用套路定义 |
| 社会 | 人怎么被分类？ | 阶级/种族/文化墙的形成与流动 | 没有叙事冲突的扁平社会 |
| 技术 | 能做什么不能做什么？ | 关键技术的存在/限制/垄断/影响 | 标准现代科技清单 |

**选择规则**：

1. 每个维度必须回答"这个设定怎么影响角色和故事"
2. 删掉一个维度后故事还能成立？能→删
3. A 类至少 1 个维度（虚构层），B 类 1-3 个，C 类选所有相关维度

## 三、背景模板写法

背景设定也使用 XML 包裹 YAML，但 XML 标签应使用具体名称，不要写通用 `<topic>`。

可选结构：

```yaml
<world_setting name="主题名称">
  概述: |
    关于世界/区域/系统的简要概括。
  历史:
    - 关键事件: |
        只写影响当前故事的事件。
  文化与社会:
    政体: 具体制度与冲突
    风俗: 影响角色行为的习惯
  重要地点:
    - 地点名: |
        地点描述 + 叙事功能
</world_setting>
```

系统/魔法/组织条目应改用具体标签，例如 `<magic_system>`、`<faction>`、`<kingdom>`、`<school>`。YAML 字段可按作品自由增减，但每个字段都要回答“它如何影响角色和故事”。

生成时不要保留模板注释；成品条目中禁止裸 `---` 文档分隔符。

## 四、总纲输出

将所有设计维度浓缩为 100-200 字的纯信息块。**零度写作**：不使用比喻、不堆叠形容词，每行都是可查询的数据陈述。

格式：

```text
【世界名】中文名称
【类型】A / B / C
【核心概念】一句话——世界最根本的决定性设定
【地理】区域划分 + 关键地点
【历史】关键事件 + 距今时间
【势力】组织名称 → 定位 → 诉求 → 关系
【规则】核心机制 + 来源 + 限制 + 代价
【社会】结构 + 形成原因 + 矛盾点
【技术】关键技术 + 限制 + 影响
```

正确：
```text
【地理】雨隐村——终年降雨的忍者村落，建筑以金属管道和塔楼连接，人口约 3000。
```

错误：
```text
【地理】雨隐村被永不停歇的雨水环抱，铁灰色的塔楼刺破灰暗的天际线，整座城市在细密的水幕中静默地呼吸着。
```

**MCP 对接**：总纲写入 plan 后，用 `create_draft_slice(draft_type="entry", id="world-summary")` 创建总纲条目。

## 四、从总纲到世界书条目

### 条目分类与配置

| order | 条目类型 | position | constant | 说明 |
|-------|---------|----------|----------|------|
| 1 | 世界观总纲 | before_char | true | 世界框架，始终存在 |
| 4 | 角色速览 | after_char | true | 多角色卡必写 |
| 10-35 | 人物设定 | after_char | 视卡型 | 单卡蓝灯，多卡绿灯 |
| 35-45 | 性格条目 | after_char | 视卡型 | 独立于人物设定 |
| 50-70 | 物品/能力 | after_char | false | 绿灯 + keys + scanDepth=2 |
| 80-98 | 场景/事件 | after_char | false | 绿灯 + keys + scanDepth=2 |
| 100 | NPC/其他 | after_char | false | 绿灯 + keys |

### 蓝绿灯决策

```text
单角色卡 → 该角色所有条目 constant=true
多角色卡 → 角色速览 constant=true + 各角色详情 constant=false + keys 覆盖所有称呼
世界观条目 → constant=true
物品/场景/NPC → constant=false + scanDepth=2
```

### 递归设置

所有条目必须同时开启：
- `preventRecursion=true`（本条目不触发其他条目）
- `excludeRecursion=true`（其他条目不触发本条目）

### 关键词设计

- 英文逗号分隔，禁用中文逗号
- 覆盖所有可能被提及的称呼：全名、昵称、外号、别称
- 场景条目：场景名、所在区域、别称
- 物品条目：物品名、简称、相关词

## 五、常见错误

| 错误 | 正确 |
|------|------|
| A 类写了真实世界常识（"东京位于关东地区"） | 只写虚构层（"阴阳厅总部设于新宿地下 30 米"） |
| B 类复述类型通用套路（"灵气是天地能量"） | 写核心差异（"灵气从界膜裂缝渗入，三大宗门各垄断一条主裂缝"） |
| C 类脑补完整编年史（创世纪元→第一纪元→...） | 只写影响当前故事的关键节点 |
| 总纲写成文学描写 | 零度写作，纯信息陈述 |
| 设计不影响故事的冗余设定（税制 12 种） | 只写影响角色行为和故事走向的设定 |
| 原创概念没有锚点（"存在晶脉资源"） | 名称→是什么→谁控制→获取规则→当前问题 |

## 六、MCP 工作流

```text
init_project
→ update_plan：记录世界观类型、维度选择、总纲
→ create_draft_slice(draft_type="entry", id="world-summary")
→ update_entry_content(id="world-summary", content=总纲内容)
→ update_entry_config(id="world-summary", changes={ entryType:"world_summary", constant:true, position:"before_char", order:1 })
→ 按条目规划表逐条创建 entry slice，并分别调用 update_entry_content / update_entry_config
→ validate_project(scope="worldbook")
```

## 七、自查清单

- 类型判定是否正确（A/B/C）？
- A 类是否只写了虚构层？
- B 类是否找到了核心差异点而非重写通用套路？
- C 类是否分层设计？
- 总纲是否 100-200 字、零度写作？
- 每个维度是否通过了"删掉后故事还能成立吗"测试？
- 原创概念是否都有功能锚点？
- 所有条目是否开启双递归？
- 蓝绿灯配置是否符合卡型？
