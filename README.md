# world-book-mcp

An MCP server for creating, modifying, validating, repairing, and exporting SillyTavern World Book JSON and `chara_card_v3` character card JSON.

## v5 Architecture

v5 uses a simple deterministic workflow:

```text
AI asks for user requirements
→ requirements and decisions are recorded in plan.md
→ draft YAML is generated/maintained from plan.md
→ long-form content is written to source files
→ MCP validates the project
→ MCP builds Tavern JSON from draft + source
```

Core model:

```text
workspace + plan.md + draft YAML + source files + deterministic builder
```

Important rules:

- `plan.md` is the only planning document. There is no `plan.yaml`.
- Character card `description` must always be an empty string.
- Character profile, personality, background, relationships, and setting content belong in World Book entries, not card description.
- Final `.card.json` and `.worldbook.json` files are generated by `generate_json`; do not hand-write final JSON.

## Workspace Structure

`init_project` creates a v5 workspace project:

```text
.worldbook/
  workspace.yaml
  projects/
    <slug>/
      project.yaml
      plan.md
      draft/
        card.yaml
        worldbook.yaml
        assets.yaml
      source/
        fields/
          first_mes.md
          greeting-01.md
        entries/
          001-world-summary.xyaml
          010-character-basic.xyaml
        mvu/
          schema.js

        html/

          statusbar.css
        regex/
          scripts.yaml
        ejs/

      reports/

        build-report.yaml
      exports/
        <name>.card.json
        <name>.worldbook.json
```

## Draft YAML

### `draft/card.yaml`

Card metadata and field references. `description` is strictly empty.

```yaml
name: Example Card
description: ""
personality: ""
scenario: ""
first_mes: ../source/fields/first_mes.md
alternate_greetings:
  - ../source/fields/greeting-01.md
mes_example: ""
creator_notes: ""
system_prompt: ""
post_history_instructions: ""
creator: ""
character_version: "1.0"
talkativeness: "0.5"
fav: false
worldbook:
  include: true
  name: Example Card
```

### `draft/worldbook.yaml`

World Book entry configuration. Entry body text lives in `source/entries/*`.

```yaml
name: Example Card
entries:
  - id: world-summary
    comment: World summary
    type: world_summary
    content: ../source/entries/001-world-summary.xyaml
    enabled: true
    constant: true
    keys: []
    secondary_keys: []
    position: before_char
    order: 1
    depth: 4
    scanDepth: null
    preventRecursion: true
    excludeRecursion: true
```

### `draft/assets.yaml`

Optional MVU / HTML / regex / EJS assets.

```yaml
mvu:
  enabled: true
  schema: ../source/mvu/schema.js
  initvar: ../source/mvu/initvar.yaml
  updateRules: ../source/mvu/update-rules.yaml
  variableList: ../source/mvu/variable-list.md
  outputFormat: ../source/mvu/output-format.md
  variableListPath: stat_data
  hideRegex: true
  beautifyRegex: true
html:
  statusbar:
    enabled: true
    html: ../source/html/statusbar.html
    css: ../source/html/statusbar.css
    variablePaths:
      - stat_data.heroine.affection
    hideRegex: true
regex:
  scripts: ../source/regex/scripts.yaml
ejs:
  enabled: false
  entries: []
```

## Responsibility Boundary

MCP only performs objective and deterministic workspace/draft/source/JSON operations: path safety, schema validation, import, repair, generation, and structural templates. Character palettes, worldbuilding design, banned-word/style review, and other context-sensitive judgments belong to the Skill workflow. After the Skill reviews or authors content, it lands changes through `write_source_file`, `write_draft`, and `configure_draft`.

## MCP Tools

| Tool | Purpose |
|------|---------|
| `init_project` | Create a v5 workspace project with `plan.md`, draft YAML, source directories, reports, and exports. |
| `update_plan` | Edit `plan.md` sections, decisions, todos, acceptance criteria, verification notes, and risks. |
| `write_source_file` | Write files under project `source/` only. |
| `read_source_file` | Safely read files under project `source/` for Skill-side subjective review. |
| `write_draft` | Rewrite or patch `draft/card.yaml`, `draft/worldbook.yaml`, or `draft/assets.yaml`; append/remove worldbook entries. |
| `configure_draft` | Infer worldbook entry config from entry type, profile, typeLists, strategyThresholds, and partOrder; preview or apply changes; rejects duplicate ids and non-`source/entries` content references. |
| `query_project` | Inspect project metadata, plan, draft, source files, reports, and exports. |
| `resume_project` | Summarize resumable progress, plan/draft differences, MVU/EJS/export state, and next actions. |
| `check_delivery` | Check delivery gates: validation, exports, reports, and entry status. |
| `validate_project` | Validate workspace/project consistency, project files, draft/source references, card rules, worldbook entries, and assets. |
| `validate_mvu` | Static MVU consistency checks for schema/initvar/variable list/output format, including simple Zod schema vs initvar comparison. |
| `apply_mvu_preset` | Write a v5-native MVU five-file template and enable assets.mvu. |
| `list_mvu_variables` | List MVU variables from initvar/schema/variable list. |
| `upsert_mvu_variable` | Add or update one MVU variable and synchronize schema/initvar/variable list/update rules/output format. |
| `remove_mvu_variable` | Remove one MVU variable and synchronize the five MVU files. |
| `rewrite_mvu_variables` | Rewrite the MVU five-file set from a complete variable list. |
| `repair_project` | Repair common imported-card issues such as non-empty description, missing recursion flags, naked status macros, and MVU root mistakes. |
| `generate_json` | Generate final Tavern `.card.json` and/or `.worldbook.json` plus build report. |
| `import_existing_json` | Import existing Tavern character card or worldbook JSON into a v5 project. |
| `import_nova_config` | Import a nova-creator-cli style YAML config into a v5 project. |
| `update_entry_status` | Update worldbook entry status, abstract, sourceRefs, part, and scope. |
| `query_entries` | Query a resumable entry manifest view and statistics. |
| `generate_tavern_sync_config` | Generate a nova tavern_sync-style bridge config under reports. |
| `create_ejs_stage_template` | Generate EJS controller + disabled stage entries for staged character profiles. |
| `list_projects` | List workspace projects. |

## Standard Workflow

```text
1. Gather user requirements.
2. init_project.
3. update_plan to record requirements and decisions.
4. write_source_file for long content.
5. write_draft or configure_draft for draft YAML.
6. Skill performs subjective text review using references, then edits source via write_source_file if needed.
7. validate_project.
8. repair_project / validate_mvu if needed.
9. generate_json.
9. Return export paths and validation summary.
```

## Import and Repair

`import_existing_json` maps existing Tavern JSON into v5:

- Card fields → `draft/card.yaml` and `source/fields/*`.
- Non-empty `description` → worldbook entry; card description remains `""`.
- Personality / scenario / creator notes → worldbook entries.
- Character book entries → `source/entries/*` + `draft/worldbook.yaml`.
- Regex scripts → `source/regex/scripts.yaml`.
- Statusbar regex → `source/html/statusbar.html` / `.css` + `draft/assets.yaml`.
- MVU system entries → `source/mvu/*` + `draft/assets.yaml`.
- TavernHelper schema script → `source/mvu/schema.js`.

Use `repair_project` after import when validation reports common repairable issues.
